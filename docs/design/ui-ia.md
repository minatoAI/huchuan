# 界面结构审计与改进（2026-11-08）

触发：L0 反馈「功能能跑，但达不到能用」。本文先给现状结构，再逐条给问题与改法。

## 一、现状结构（按实现，不按设计稿）

```
P0 自检（自动进 / 失败只给重试）
└─ P1 用户名（首次设名）
   └─ P2 群列表 ──────────── 搜索 / 设置 / +
      ├─ P3 群内文件 ──────── 成员 / 添加文件
      │  ├─ 添加文件弹层 ──── 本机文件（SAF） / 磁力链接（输入框）
      │  ├─ P6 成员
      │  └─ P4 文件详情 ───── 激活·休眠开关 / 进度·速度 / 评论 / 「…」
      │     └─ 「…」菜单 ──── 单文件限速 / 分享链接 / 公开到群外 / 移除
      │        └─ P8 分享链接（二维码 + 链接 + 有效期）
      ├─ P5 新建或加入群
      └─ P7 设置（抽屉） ──── 用户名 / 全局限速 / 通知 / 跨网发现 / 网络状态 / 分享管理
         └─ P9 分享管理（列表 + 撤销）
```

入口统计：**P8 唯一入口在 P4 的「…」菜单里**，P9 唯一入口在 P7。群内没有文件就没有 P4，也就没有分享入口。

## 二、逐条问题

### 1. P4 的激活/休眠开关是什么

设计依据：`docs/design/product-spec.md` P4「主动能：控制该文件在本机的激活/休眠」，并写了「全 App 只有这一个开关」。

语义：**激活 = 参与传输**（做种或下载），**休眠 = 保留记录但不参与传输**（不占上行、不需要保持连接、公开条目还会退出公开会话）。用途：把带宽让给别的文件、省电、暂时不想分享。

问题：界面上只有一个开关，没有任何一处说明"关掉会怎样"。用户看到「激活/休眠」两个词，并不知道是"是否参与传输"。

改法（不改结构）：开关下面补一行当前后果，例如「正在做种，成员可从你这里下载」/「已休眠，不占带宽，成员暂时下不到」。一行字，不加控件。

### 2. 回复没有层级、也没有取消

现状：点评论行 → 输入框 hint 变成「回复 」，但列表里回复与主评论**平铺显示**，看不出谁回谁；也没有取消回复目标的按钮，误点后只能退出整页。

改法：
- 列表按 parent 渲染两级（缩进 + 左侧竖线），超过两级压平到第二级（GitHub issue 的做法）；
- 输入框上方出现「回复 @张三 ×」，点 × 取消目标；
- 返回键先取消回复目标，再退出页面（已有输入焦点时不拦截）。

### 3. 长文件名点不到、看不全

现状：行内单行显示，长名被截断且点击区域跟着文字走。

改法：整行可点（不是文字可点）；名称用**单行中间省略**（保留扩展名），点进 P4 显示完整名（可换行，最多两行）。

### 4. 评论不能删、不能改

设计现状：协议里 kind=2 是墓碑、M1 不发（`protocol.md §6` 写「M1 不可删」），编辑从一开始就不支持（追加日志）。

改法：
- M1 补**删除自己发的评论**（发墓碑），列表隐藏；
- 编辑不做——追加日志里"编辑"语义要么变成墓碑+新条目（读者看到两条），要么破坏签名链。不做比做错好。

### 5. P7 限速开关逻辑反了

现状：「不限」开关打开 = 不限速，关掉才限速，且阈值输入框一直可见。

改法：开关改为**「限制速度」**；关 = 不限速、两个输入框隐藏；开 = 显示上行/下行输入框。这是业界通行写法（qBittorrent、Transmission 同构）。

### 6. 分享链接入口太深

现状：P2 → P3 → P4 → 「…」→「分享链接」。用户要先把自己文件放进群，才可能分享。

行业做法：分享是**对象上的动作**，入口跟着对象（AirDrop、文件管理器"分享"）。但"对象"可以选得更浅一层：文件行本身。

建议（三选一，我推荐 A）：
- **A**：P3 文件行右滑/长按 → 菜单含「分享链接」。比 P4 少一层，且仍是"对文件操作"。
- **B**：P9 增加「新建分享」按钮，从群内文件里挑一个。分享管理页从"只看列表"变成"列表 + 新建"。
- **C**：P2 增加常驻「分享」入口。最易发现，但违反「一页一功能」，且与"先有文件"冲突。

### 7. 其它缺口（按"群 = Git 仓库"的类比）

| 缺什么 | 类比 | 影响 |
| --- | --- | --- |
| 文件列表不能排序/筛选 | git log --sort | 文件多了找不到 |
| 全局搜索只搜群名，不搜文件 | grep | 记不住在哪个群 |
| 评论不能折叠/分页 | issue 分页 | 几百条后加载慢、滚动长 |
| 没有"我发起的分享"状态提示 | — | 不知道有没有人在下载 |
| 文件行不显示上传者 | git blame | 不知道谁给的 |

## 三、优先级

1. 回复层级 + 取消目标（可用性硬伤）
2. 限速开关逻辑（语义反了）
3. 长文件名（看不全就选不对）
4. 删除自己的评论（缺失的撤销）
5. 激活/休眠的后果说明（一行字）
6. 分享入口层级（要么 A 要么 B）

前 5 项不需要产品决策，按上文改即可；第 6 项需要拍板选哪个入口。
