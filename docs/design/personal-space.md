# 个人空间（链接分享的独立入口）

决定时间：2026-11-08，由 L0 拍板。

## 结论

应用内置一个**个人空间**：一个特殊的、不可被加入的本地群，专门用来放要分享链接的文件。用户不需要先建群、也不需要把文件发给任何人，就能创建分享链接。

## 为什么

现状：分享链接的入口在 P4「…」菜单，而 P4 必须先有群、群里有文件。这只对"已经在群里共享的文件"成立，对"我想把桌面上的一个文件临时发给别人"完全不成立——而后者才是链接分享的主要用法。

## 形态

| 属性 | 取值 |
| --- | --- |
| 名称 | 我的分享（固定，不可改） |
| 在 P2 | 固定置顶，图标与普通群不同，不显示成员数 |
| 成员 | 只有本机自己；成员页显示一个人 |
| 邀请码 | 不生成，不显示 |
| mDNS | **不广播**，不响应任何加入请求 |
| 消息层 | 不监听、不参与群协议；不走 message port |
| 文件 | 与群文件同一套存储与做种代码（复用，不另写） |
| 删除 | 不可删除；删文件是删文件，不是删空间 |
| 链接分享 | P4「…」→「分享链接」可用；P9 也可从这里新建 |

## 与普通群的区别（实现要点）

1. 创建：首次启动或首次进入时自动创建，gid 固定派生（例如 HKDF(identity, "personal")），不写邀请码。
2. 不发 mDNS：GroupRuntime 的 announce 路径要按 isPersonal 跳过；同样跳过 tracker 注册。
3. 不接受 join：消息层对该 gid 的 join 一律拒绝（对端不该知道它存在，但万一有旧数据也拒）。
4. 不显示在"加入群"的候选里、不参与未读角标统计以外的功能。
5. 兼容：旧 state.json 没有个人空间时，启动后补建，已有数据不受影响。

## 入口结构（改后）

```
P2 群列表
├─ 我的分享（置顶，个人空间）
│  └─ P3 文件列表 ── 添加文件（本机/磁力）
│     └─ P4 ── 「…」→ 分享链接 → P8
└─ 普通群 …
P7 → P9 分享管理 ── 新建分享（可选：从个人空间或群文件挑）
```

## 不做

- 不做多个人空间
- 不做"把群文件移进个人空间"（先不做，避免复制语义混乱）
- 不把个人空间当普通群的模板
